# transcribe-anything — спецификация

Self-hosted сервис транскрибации: любой медиафайл или ссылка → текст с таймкодами → опциональное AI-саммари по пресетам.

Документ фиксирует решения, принятые на этапе проектирования. Каждое решение — с обоснованием, чтобы позже не переигрывать его вслепую.

---

## 1. Архитектурные принципы

1. **В бэкенде нет ML.** Ни torch, ни whisper, ни весов моделей. STT и LLM — внешние HTTP-сервисы, говорящие по OpenAI-совместимому протоколу. Образ остаётся лёгким, тесты не требуют GPU.
2. **STT и LLM — два независимых клиента**, а не общая абстракция «AI-провайдер». У них разные протоколы (`/v1/audio/transcriptions` vs `/v1/chat/completions`), разные провайдеры и разные режимы отказа. Общий интерфейс был бы ложным обобщением.
3. **Сырые данные неизменяемы.** Ответ STT хранится как есть; все производные (txt/md/srt/vtt, правки пользователя) вычисляются поверх. Смена формата экспорта не требует перетранскрипции.
4. **API-first.** Всё, что делает UI, доступно по REST с Bearer-токеном.
5. **Один том данных.** Бэкап = `tar czf backup.tgz /data`.

## 2. Пайплайн

```
источник → скачивание/загрузка → ffprobe (определение формата)
        → ffmpeg → Opus 16 kHz mono 32 kbps (ogg)
        → нарезка по границам тишины (если > 15 мин)
        → STT по чанкам (verbose_json) → склейка с offset
        → транскрипт с сегментами и таймкодами
        → [опционально] диаризация → мердж спикеров
        → [опционально] LLM-саммари по пресету
```

### 2.1. Ingest

Pluggable `SourceResolver` с реализациями:

| Тип | Описание |
|---|---|
| `upload` | multipart, **стриминг напрямую на диск**, никогда не в память. `MAX_UPLOAD_SIZE` по умолчанию 5 GB |
| `remote_url` | прямая ссылка на медиафайл, httpx-стриминг |
| `ytdlp` | YouTube/Twitch/VK и ещё ~1800 сайтов. Тянем только `bestaudio`. Забираем метаданные: название, автор, обложка, дата |

Resumable-загрузку (tus) не делаем — избыточно для LAN-селфхоста.

### 2.2. Нормализация

Целевой формат — **Opus 16 kHz mono 32 kbps в ogg**:

- ~14 MB/час против 115 MB/час у WAV и 57 MB/час у FLAC;
- кодек спроектирован под речь, на точность распознавания не влияет;
- поддерживается всеми OpenAI-совместимыми эндпоинтами;
- укладывается в лимит 25 MB облачных API почти для двухчасовых записей.

**Оригинал удаляется сразу после успешной нормализации** (`KEEP_ORIGINAL=false` по умолчанию). Иначе диск кончается за неделю на видеофайлах.

### 2.3. Чанкинг

`STT_CHUNKING=auto|always|never`, по умолчанию `auto` — чанкуем, если длительность > 15 минут.

Границы ищем через `ffmpeg -af silencedetect`: режем в паузе, ближайшей к целевым **10 минутам**, жёсткий максимум — **15 минут**. Никакого ML, только ffmpeg.

Почему не фиксированные интервалы: разрез посреди слова заставляет Whisper галлюцинировать или терять фразу на стыке. Это тихий баг — текст выглядит связным, но фрагмент пропал.

Что даёт чанкинг помимо обхода лимитов: честный прогресс (`чанк 3/17`), ретрай одного чанка вместо всего файла, параллельная отправка 2–3 чанков.

### 2.4. STT

- Всегда `response_format=verbose_json` — нужны `start`/`end` сегментов. Без них невозможны ни субтитры, ни синхронный плеер, а добавить их позже = переделать хранение.
- К сегментам каждого чанка прибавляется его offset.
- **Язык детектится один раз на первом чанке и принудительно передаётся во все остальные.** Иначе разные чанки распознаются разными языками. В UI — селектор с дефолтом `auto`.
- Поле `prompt` (initial prompt Whisper) прокидывается из UI: список терминов и имён радикально повышает точность их распознавания.

### 2.5. Саммари

- **Auto map-reduce по бюджету токенов.** Считаем размер транскрипта, сравниваем с `context_tokens` провайдера (дефолт 8192 — пессимистично и безопасно). Влезает → один запрос; не влезает → map по чанкам → reduce из частичных саммари.

  Причина пессимистичного дефолта: Ollama с `num_ctx=8192` молча обрезает вход и отдаёт саммари только по началу файла. Результат выглядит правдоподобно, но неверен — худший класс багов.

- **Промежуточные map-результаты сохраняются.** Reduce падает регулярно (локальные модели любят отдать невалидный ответ) — перегонять 17 чанков заново недопустимо.
- Ответ стримится в UI через SSE.
- Транскрипция и саммари — **независимые джобы**: саммари перезапускается с другим пресетом или моделью, не трогая STT.

### 2.6. Диаризация (этап 6)

Стандартного OpenAI-совместимого эндпоинта не существует — значит отдельный сервис со **своим контрактом**: `POST /diarize → [{start, end, speaker}]`. Контейнер `diarizer` выключен по умолчанию.

**Схема готовится сразу**, реализация — позже. Мердж: спикер присваивается сегменту по максимальному перекрытию интервалов. Переименование (`SPEAKER_01` → «Марина») — правка одной строки в `speakers`, транскрипт перерисовывается сам.

## 3. Данные

### 3.1. Схема (основное)

```
users(id, username, password_hash, is_admin, created_at)
api_tokens(id, user_id, name, token_hash, last_used_at)

providers(id, kind[stt|llm], name, base_url, api_key_encrypted,
          default_model, context_tokens, extra_json, is_default)

jobs(id, owner_id, source_type, source_ref, title, status, progress,
     language, prompt, stt_provider_id, stt_model,
     sha256, duration_sec, error_message, worker_id, heartbeat_at,
     created_at, started_at, finished_at)

transcripts(id, job_id, raw_json, language, created_at)
segments(id, transcript_id, idx, start, end, text, edited_text, speaker)
speakers(id, job_id, label, display_name)

presets(id, owner_id, name, description, system_prompt, user_template,
        model_override, provider_id, temperature, output_format, is_builtin)
summaries(id, job_id, preset_id, status, content, partials_json,
          model_used, created_at)

shares(token, job_id, created_at, expires_at)
segments_fts  -- FTS5 виртуальная таблица + триггеры
```

`owner_id` присутствует с первой миграции — вкрутить его позже без переписывания всех запросов невозможно.

Правки живут отдельным слоем: `raw_json` неизменяем, `segments.edited_text` — поверх. Экспорт берёт `COALESCE(edited_text, text)`. Это бесплатно даёт «сбросить правки» и «перетранскрибировать другой моделью, сохранив правки для сравнения».

### 3.2. Файлы

```
/data
├── db/app.db              (+ -wal, -shm)
├── media/{job_id}/audio.ogg      ← единственный долгоживущий артефакт
├── tmp/{job_id}/                 ← чанки, чистятся по завершении
└── secret.key
```

- Чанки удаляются в `finally` **и** сборщиком-сиротой при старте воркера (иначе `kill -9` оставляет мусор навсегда).
- Транскрипты и саммари не удаляются автоматически никогда — весят килобайты, содержат всю ценность.
- `AUDIO_RETENTION_DAYS=0` (вечно). По истечении удаляется только `audio.ogg`, запись остаётся с пометкой «аудио удалено».

Аудио хранится ради **синхронного плеера**: клик по сегменту — перемотка, текущая фраза подсвечивается. Ради этого и делались таймкоды.

### 3.3. Дедупликация

SHA-256 считается при загрузке. Если файл уже транскрибирован **той же моделью и языком** — предлагаем открыть существующий результат. Именно предлагаем, а не редиректим молча: иногда перегнать нужно осознанно.

## 4. Очередь и воркер

**Отдельный контейнер-воркер**, тот же образ, другой entrypoint. Брокера нет — очередь это таблица `jobs`.

Claim в одной транзакции:

```sql
UPDATE jobs SET status='running', worker_id=?, started_at=?
WHERE id = (SELECT id FROM jobs WHERE status='queued'
            ORDER BY created_at LIMIT 1)
RETURNING *;
```

SQLite в режиме **WAL** + `busy_timeout`.

**Recovery при старте:** джобы в статусе `running` с протухшим heartbeat возвращаются в `queued`.

Почему не in-process: рестарт API рвал бы активные джобы, ffmpeg делил бы CPU с обработкой запросов, `--reload` в разработке убивал бы работу. Почему не Redis/Celery: десятки джоб в день, а не тысячи в минуту — брокер здесь налог на сложность.

**Отмена** убивает процесс ffmpeg и рвёт HTTP к STT, а не просто ставит флаг. Иначе отменённая транскрипция продолжает жечь GPU.

**Ретраи** — только на сетевых ошибках (5xx, таймаут, connection reset), экспоненциальный бэкофф, 3 попытки, **на уровне отдельного чанка**. На 4xx падаем сразу.

**Ошибки человекочитаемые**: не `HTTPError: 502`, а «STT-сервер недоступен по адресу http://speaches:8000 — проверьте, запущен ли контейнер».

## 5. Провайдеры и конфигурация

Гибрид: **env как bootstrap-seed → дальше источник истины БД**. При первом старте пустая таблица заполняется из переменных окружения; потом всё правится в UI без рестарта.

Обязательные элементы UI:

1. **Кнопка «Проверить подключение»** — дёргает `GET /v1/models`. 90% проблем селфхостинга это `localhost` вместо `host.docker.internal`, и искать это в логах воркера — пытка.
2. **Список моделей из `/v1/models`**, а не текстовое поле с опечатками. Его отдают Ollama, LM Studio, vLLM, OpenAI.
3. **Несколько провайдеров одновременно**: локальная модель для рутины, облако для качества. Выбор провайдера и модели — на уровне пресета.

Ключи шифруются Fernet, ключ в `/data/secret.key` (генерируется автоматически при отсутствии). **В API-ответах ключ всегда замаскирован** (`sk-...abcd`) и никогда не возвращается целиком.

Осознанное ограничение: ключ шифрования лежит рядом с шифруемыми данными, то есть защищает от случайной утечки через бэкап БД, а не от локального злоумышленника. Для селфхоста порог входа важнее криптографической чистоты — это должно быть написано в README прямым текстом.

## 6. Авторизация

`AUTH_MODE=builtin|proxy|disabled`.

- **`builtin`** (по умолчанию): argon2, сессия в **httpOnly cookie**. Не JWT в localStorage — распределённости нет, а localStorage это XSS-уязвимость по умолчанию.
- **`proxy`**: доверяем `X-Remote-User` от Authelia/authentik.
- **`disabled`**: осознанный выбор для localhost, с жёлтым баннером в UI.

**Setup-wizard при первом запуске**: пустая база → страница создания админа. Никаких дефолтных `admin/admin` и никакого обязательного редактирования env перед стартом.

**Открытой регистрации нет** — админ заводит юзеров вручную. Открытая регистрация на инстансе, торчащем наружу, это приглашение майнить чужой GPU.

**Транскрипты приватные по умолчанию**, шаринг — явной кнопкой: публичная read-only ссылка по случайному токену.

## 7. Фронтенд

**Vite + React + TypeScript, SPA.** Next.js не нужен: приложение целиком за авторизацией, SEO отсутствует, SSR нечего рендерить, MUI требует `'use client'` почти везде. Главное — Next.js это лишний Node-контейнер в проде, а Vite собирается в статику, которую отдаёт сам FastAPI.

OG-превью для share-ссылок решаются тем, что FastAPI отдаёт на `/s/{token}` HTML с мета-тегами и монтирует то же SPA. Тридцать строк против целого фреймворка.

**MUI + собственная M3-тема.** Готовой реализации Material 3 Expressive в MUI нет (проверено по документации). «Экспрессивность» достигается темой: палитра генерируется через `@material/material-color-utilities` из seed-цвета, крупный `shape.borderRadius`, `cssVariables: true` + `colorSchemeSelector` для light/dark.

`material-web` от Google отвергнут: настоящий M3, но библиотека в maintenance-режиме, компонентов мало, таблиц и дейтпикеров нет.

**Реалтайм — SSE, не WebSocket.** Поток односторонний, SSE переживает reconnect автоматически, проходит любой reverse-proxy без апгрейда протокола и отлаживается через `curl`. Тот же механизм для прогресса джоб и для стриминга саммари.

### 7.1. Мультиязычность (правка от 2026-08-21)

Интерфейс мультиязычный, стартовые локали — **en/ru**. Отсюда следует правка контракта ошибок из §4:

**API никогда не возвращает переведённый текст.** Ответ об ошибке — `{"error": {"code", "params", "message"}}`, где `code` стабилен и машиночитаем, а текст рисует фронт из своего бандла. `message` остаётся английским фолбэком для потребителей без слоя переводов — curl, вебхуков, скриптов.

Иначе «человекочитаемая ошибка» из §4 означала бы, что язык интерфейса задаётся переменной окружения бэкенда, а не выбором пользователя в UI. Параметры («STT-сервер недоступен по адресу X») уезжают в `params` и подставляются при переводе.

Язык хранится в `localStorage`, определяется по `navigator` при первом заходе. i18next + react-i18next.

Код, комментарии, идентификаторы и коммит-сообщения — **только английские**. Русский живёт в `frontend/src/locales/ru.json` и в этом документе.

Ключевые экраны: список джоб с прогрессом → экран транскрипта (плеер + синхронная подсветка + правка сегментов + переименование спикеров) → панель саммари с историей → настройки провайдеров → редактор пресетов → поиск по архиву.

### 7.2. UI-библиотека: shadcn/ui вместо MUI (правка от 2026-08-22)

MUI из §7 заменён на **Tailwind v4 + shadcn/ui с темой из tweakcn**. Причина не в самом MUI, а в том, ради чего он выбирался: собственная M3-тема через `@material/material-color-utilities` означала генерацию палитры в рантайме и переопределение компонентов темой — то есть слой, который надо поддерживать, чтобы получить внешний вид, который всё равно не является настоящим Material 3.

shadcn/ui даёт то же самое дешевле: компоненты копируются в `components/ui/` и принадлежат нам, а вся тема — два oklch-блока в `index.css`. Отсюда инвариант: **UI называет цвета, но не выбирает их** — компоненты пользуются семантическими токенами (`bg-primary`, `text-muted-foreground`), значения написаны в одном месте, замена блока заменяет тему. К набору shadcn добавлены `--warning` и `--success`: приложение сообщает о деградированной конфигурации и о завершённой работе, а цвета под это в дефолтном наборе нет.

## 8. Экспорт и автоматизация

Форматы генерируются на лету, ничего не хранится предрассчитанным:

`txt` (абзацами по паузам), `md` (таймкоды, спикеры, метаданные в шапке), `srt`, `vtt`, `json` (сырой ответ STT).

`docx` и `pdf` не делаем — тяжёлые зависимости ради формата, в который всё равно копируют из markdown.

К каждому формату — **опции рендера**: с таймкодами или без, со спикерами или без. Это решает, годится ли выгрузка для вставки в Obsidian/Notion. **Кнопка «скопировать»** рядом с каждой — ей пользуются чаще, чем скачиванием.

**Автоматизация — только REST + webhook.** Интеграции с Notion/Obsidian/Google Docs не делаем: каждая это OAuth, рефреши токенов, ротация и вечная поддержка чужого API. Webhook (POST с JSON результата на заданный URL) плюс Bearer-токены покрывают те же сценарии при нулевой поддержке чужих контрактов.

**Полнотекстовый поиск — SQLite FTS5.** Одна виртуальная таблица и триггеры, но превращает архив из списка файлов в базу знаний.

## 9. Пресеты саммари

Хранятся **в БД с CRUD в UI** (не в YAML, не в коде). Возможность на лету сделать пресет «выжимка для моего Obsidian, только буллеты, по-русски» — главная причина хостить это у себя, а не пользоваться готовым сервисом.

Поля: `system_prompt`, `user_template` с плейсхолдерами `{transcript}`, `{title}`, `{duration}`, `{language}`, `model_override`, `provider_id`, `temperature`, `output_format`.

Seed по умолчанию: **Краткое резюме**, **Подробный конспект по разделам**, **Action items / решения**, **Ключевые тезисы буллетами**, **Протокол встречи**, **Custom** (пустой шаблон).

История саммари сохраняется: применил три пресета — видишь три результата, сравниваешь, лишний удаляешь.

## 10. Docker

Один `docker-compose.yml` с профилями:

| Сервис | Профиль | Назначение |
|---|---|---|
| `api` | всегда | FastAPI + статика фронта |
| `worker` | всегда | Тот же образ, `command: python -m app.worker` |
| `speaches` | `stt-cpu` / `stt-gpu` | STT из коробки |
| `ollama` | `llm` | Для тех, у кого нет облачных ключей |
| `diarizer` | `diarize` | Этап 6 |

`docker compose up -d` поднимает только `api` + `worker`. `--profile stt-gpu --profile llm` — автономный стек одной командой.

**Образы публикуются в GHCR**, в compose по умолчанию `image:`, а не `build:`. Разница между «`up -d`, 40 секунд» и «клонируй, собирай фронт, жди десять минут» — это разница между «попробовал» и «закрыл вкладку». Сборка живёт в `docker-compose.dev.yml` с bind-mount и hot-reload.

- **Multi-arch (amd64 + arm64)** через buildx в CI — Apple Silicon и ARM-мини-серверы очень частый хост для такого.
- **Миграции применяются автоматически при старте `api`** (Alembic `upgrade head`). «Зайди в контейнер и накати миграции» — гарантированный багрепорт после каждого обновления. Воркер миграции не трогает, ждёт готовности схемы.
- `python:3.13-slim`, ffmpeg из apt, **`yt-dlp` отдельным последним слоем** (обновляется чаще всего), процесс от non-root, `HEALTHCHECK` у обоих сервисов.
- **Порт по умолчанию 8927**, не 8000 — он занят у половины селфхостеров.
- **Встроенного HTTPS нет.** Ставится за своим Caddy/Traefik/nginx; мы только уважаем `X-Forwarded-*`, чтобы share-ссылки генерировались с правильной схемой и хостом.
- В комментарии к профилю `llm`: «если у вас уже есть Ollama — не поднимайте этот профиль, укажите `http://host.docker.internal:11434/v1`».

## 12. Тесты

- **Внешний HTTP мокается стаб-сервером, а не патчами.** Поднимаем маленькое ASGI-приложение, отвечающее как `/v1/audio/transcriptions` и `/v1/chat/completions`, подставляем его `base_url`. Не `respx`, не `unittest.mock`.

  Причина: стаб проверяет, что мы шлём корректный multipart и корректный JSON. Патч проверяет только что мы вызвали собственную функцию. Плюс стаб ловит регрессии вида «сменили версию httpx — поехал boundary».

- **ffmpeg не мокается вообще.** Он есть в образе и в CI. Тестовое аудио генерируется им же: `ffmpeg -f lavfi -i "sine=frequency=440:duration=3"`. Ноль бинарников в репозитории, и проверяются реальные аргументы командной строки — там и живут баги.

- **Границы системы:** ffmpeg, STT-HTTP, LLM-HTTP, yt-dlp, файловая система. Собственные репозитории, сервисы и воркер не мокаются никогда — тест дёргает публичный API через `httpx.AsyncClient` и смотрит наблюдаемый результат.

- **Чанкинг по тишине — property-based тест.** Инварианты: чанки покрывают всю длительность без дыр, ни один не длиннее максимума, склеенные таймкоды монотонно возрастают. Ручными примерами это не покрыть, а баг там тихий: текст выглядит нормально, но пять секунд посередине пропали.

- **SQLite-конкуренция проверяется явно**: два воркера параллельно берут задачи, ни одна не достаётся двоим. Claim-паттерн ломается ровно так, и в одиночном тесте это невидимо.

## 13. Этап 7: навигация, настройки, архив (план от 2026-08-22)

Этапы 0–6 строили пайплайн, а интерфейс к нему нарастал по одному экрану на этап: список джоб стал главной страницей, поиск и пресеты — пунктами в шапке, настройки — страницей с одними API-токенами. Этап 7 не добавляет к пайплайну ничего; он приводит поверхность в порядок и закрывает то, чего в ней не хватало с самого начала: удаление, пользователей, редактирование провайдеров.

### 13.1. Три экрана

**Главная — что сейчас происходит. История — что у меня есть.**

Сегодня `/` показывает и загрузку, и очередь, и весь архив одним списком. Разделяем по смыслу, а не по длине: на главной остаётся дропзона, поле ссылки, быстрые настройки и **только незавершённые работы** плюс те, что завершились в этой сессии; всё терминальное живёт в Истории.

Завершившаяся работа не исчезает с главной сразу — иначе список сам себя опустошает ровно в тот момент, когда человек на него смотрит. «Сессия» живёт в памяти приложения: ушёл в Историю и вернулся — карточки на месте, перезагрузил страницу — очередь честно пуста. `sessionStorage` не берём: перезагрузка это и есть жест «начать заново», а два источника правды дороже пользы.

Отвергнуто:

- **Редирект на страницу работы после отправки** — ломает главный сценарий, пачку файлов подряд. SSE-поток и так устроен как одно соединение на весь список (`watchJobs`), а не на работу.
- **«Последние N» на главной** — два списка с одинаковыми строками и вечный вопрос, какой из них настоящий. Вместо этого одна строка со счётчиком: «в истории 312 записей →».

**Поиск перестаёт быть экраном** и становится строкой в Истории: пустая — весь архив по дате, заполненная — те же строки, но совпавшие, с подсветкой и переходом на секунду. Это один и тот же список, отфильтрованный двумя разными способами; держать под него отдельный адрес незачем.

**Пресеты переезжают в настройки.** Это конфигурация того, как считается саммари, редактируемая раз в месяц и используемая через выпадающий список на странице работы, — ровно как провайдеры. В шапке остаётся три вещи: «домой», поиск, настройки.

### 13.2. Быстрые настройки

На главной — язык записи, диаризация, пресет авто-саммари. Под раскрывашкой — выбор провайдера и модели (`is_default` подразумевает, что провайдеров может быть несколько: локальный быстрый для черновика, облачный точный для важного).

Критерий отбора: в быстрые настройки попадает то, что является свойством **записи**, а не инстанса. Язык нельзя знать заранее и он меняется от файла к файлу — сейчас его вообще нельзя задать, он угадывается по первому чанку и навязывается остальным, и это самая дорогая ошибка в системе: пять секунд английского вступления уводят двухчасовой русский разговор не туда, а переделка означает гнать всё заново. Авто-саммари попадает по другой причине: превращает «загрузил → подождал → зашёл → нажал → подождал» в один шаг.

Чанкинг остаётся инстанс-уровневым env. У него нет правильного пользовательского ответа: человек не знает, что выбрать, а неверный выбор тихо портит качество.

**Значений по умолчанию в настройках нет.** Главная запоминает последний выбор в `localStorage`. Реальный сценарий — «заливаю пять записей подряд, все на русском, все с диаризацией», и память последнего выбора обслуживает его без единой строки бэкенда. Дефолты в настройках стоили бы миграции и эндпоинта, а первым же следствием дали бы вопрос «почему на главной английский, если в настройках написан русский».

Новые поля на работе: `language_hint`, `auto_summary_preset_id`.

### 13.3. Настройки: шесть разделов, шесть адресов

`/settings/{users,history,appearance,providers,presets,api}`, боковое меню, `/settings` редиректит на первый доступный раздел.

Адреса, а не вкладки: предупреждение «нет STT-провайдера» на главной должно вести прямо в нужный раздел, а не в «поищи сам»; каждый раздел грузит своё (пользователей, размер диска, провайдеров, токены) и не тянет остальные пять; админский гейт становится отсутствующим пунктом меню и редиректом, а не условным рендером внутри одного компонента.

**Пользователи.** Сегодня их завести нельзя ничем: `POST /api/setup` работает один раз, других эндпоинтов нет, а `is_admin` не проверяется нигде — флаг есть, прав он не даёт. Изоляция при этом готова: `owner_id` фильтрует работы, пресеты и саммари, так что второй пользователь сразу получает приватный архив.

Раздел даёт админу список с созданием, назначением админа и удалением, а обычному пользователю — только свой аккаунт со сменой пароля. Отсюда:

- Появляется настоящий `admin_required` — иначе любой сможет выдать себе админа через API.
- В `proxy` список только на чтение: личности не наши, аккаунт заводится сам при первом входе, пароля у нас нет. В `disabled` раздел скрыт целиком.
- **Удаление пользователя с работами отклоняется** и требует явного «удалить вместе с N записями». Тихое каскадное удаление гигабайтов аудио по клику чинится только из бэкапа.
- **Последний админ не удаляется и не разжалуется** — иначе инстанс запирается снаружи.

**Кто админ в `proxy`.** Пользователи из заголовка заводятся всегда с `is_admin=False`, то есть инстанс за Authelia получил бы ноль админов и стал бы ненастраиваемым. Решение: `ADMIN_USERS=alice,bob` в env, сверка имени при каждом запросе. Список **дополняет** флаг в базе, а не заменяет: админ = `is_admin` **или** имя в списке, иначе включение переменной молча разжалует админа из мастера первичной настройки. Работает одинаково во всех трёх режимах и в `builtin` служит спасательным тросом при потерянном пароле.

Отвергнуто: «первый вошедший становится админом» — неисправимо изнутри, если первым зайдёт не тот человек. Группы из второго заголовка (`X-Remote-Groups`) архитектурно правильнее, но требуют от оператора настроенной передачи групп — как дополнение позже, как единственный механизм рано.

**История (хранение).** Удалить транскрибацию сегодня нельзя вообще: `DELETE` есть у шаринга, токенов, пресетов и саммари, у работы нет. Архив только растёт.

Дорогое и ценное здесь — разные вещи: час записи это десятки мегабайт `ogg`, транскрипт того же часа — десятки килобайт. Поэтому политик две и они раздельные: **удалять аудио старше N дней, оставляя текст** и, отдельным переключателем, **удалять работу целиком старше M дней**. Первая освобождает практически всё место, не теряя практически ничего, и деградирует мягко — плеера просто не будет, а это состояние уже описано в коде (`has_audio`, `audio_unavailable`).

**Обе по нулям по умолчанию.** Self-hosted архив, который сам молча съедает данные, — худший из возможных сюрпризов. Подметает воркер своим же циклом опроса, раз в час; отдельный планировщик не нужен. Занятое место показывается разбитым на «аудио» и «остальное» — без этой цифры настройка хранения это гадание.

**Внешний вид.** Тема и язык остаются в шапке — язык нужен на экране входа, куда настройки не пускают. Раздел даёт их же плюс то, чему в шапке места нет: таймкоды по умолчанию (сейчас `showTimestamps` включён жёстко и сбрасывается на каждой странице), плотность списков, объяснение что даты следуют языку интерфейса, а не браузеру.

Пикер акцентного цвета не делаем: значения живут в двух oklch-блоках `index.css`, и в этом весь смысл — тема заменяется заменой блока. Хранение предпочтений остаётся в браузере: тема должна примениться до первого запроса, иначе вспышка светлой темы на тёмной.

**Провайдеры.** Экран, обещанный в §5 и не построенный: модель полная, ключ на чтении маскируется, `seed.py` засевает только пустую установку — наружу торчит один `GET`. Достраиваем CRUD, и четыре детали решаются так:

- **Ключ — только на запись.** Маску обратно не принимаем никогда, иначе первое сохранение формы затрёт настоящий ключ маской. Контракт: поля нет — оставить, пустая строка — стереть, строка — заменить.
- **`is_default` — ровно один на вид, в одной транзакции.** Плюс частичный уникальный индекс на `(kind) where is_default`, чтобы это нельзя было сломать в обход API.
- **Проверка соединения принимает черновик**, а не только сохранённый `id`: проверять хочется до сохранения. Формулировка «эндпоинт отвечает», а не «всё работает», — `/v1/models` есть не у всех OpenAI-совместимых серверов.
- **Удаление** сбрасывает `Preset.provider_id` в `null` (пресеты возвращаются к дефолтному провайдеру — их штатное поведение), в диалоге показывается, скольких это коснётся. Запрещён один случай: удалить единственный STT-провайдер.

Ловушку с повторным засевом (удалил всех, перезапустил — вернулись из env) оставляем как спасательный трос и пишем о ней строкой под списком.

**API.** Токены, вебхук и документация одним разделом: класть ключи в одно место, а объяснение, что с ними делать, в другое — значит гонять человека между ними.

Вебхук переезжает из env в базу по образцу провайдеров (env засевает, дальше правит база) и получает кнопку «отправить тестовый вызов». Сейчас он отлаживается загрузкой настоящего файла и ожиданием, потому что срабатывает один раз и не повторяется.

Документация **не пишется руками**: второй экземпляр справочника протухнет за этап. В разделе — четыре вещи, которых нет в OpenAPI: базовый адрес этого инстанса из `window.location`, готовый `curl` от создания работы до транскрипта, ссылка на `/docs`, и контракт ошибок из §7.1 — `code` + `params` машиночитаемы, `message` английский фолбэк. На последнее напорется первый же, кто начнёт парсить ответы.

### 13.4. Архив

Один список, не два. «Файл» здесь не существует отдельно: у каждой записи ровно одно аудио в `media/{job_id}/`, оно не переиспользуется и не может принадлежать двум работам. Отдельная вкладка «Файлы» дала бы те же строки с колонкой размера и вечный вопрос «я удалил там — оно пропало здесь?».

В строке: размер, есть ли ещё аудио, все терминальные статусы с фильтром (упавшая полчаса назад загрузка не должна становиться ненаходимой), удалить целиком или снять только аудио. Плюс массовое выделение — раз появляется удаление, удалять по одному сто записей это не работа.

**Удаление подтверждается диалогом, а не отменяется тостом.** Отмена требует `deleted_at`, фильтра в каждом запросе и отложенной чистки файлов; операция редкая и не мгновенная по смыслу.

**Работа с публичной ссылкой удаляется без вопросов**, ссылка начинает отвечать `share_not_found` — её штатное поведение при отзыве. Предупреждение «на неё есть ссылка» останавливало бы удаление ровно тогда, когда его чаще всего и хотят: когда ссылка утекла.

### 13.5. Порядок сборки

Порядок неслучаен: гейт раньше разрушающих операций, автоматика позже проверенного вручную удаления.

| # | Кусок | Почему здесь |
|---|---|---|
| 1 | Переезд навигации без единой новой возможности | Только перекладывание — ревьюится глазами, проверяется существующими тестами |
| 2 | `admin_required`, `ADMIN_USERS`, провайдеры целиком | Делает инстанс настраиваемым без `.env`; гейт нужен до разрушающих операций |
| 3 | `DELETE /api/jobs/{id}`, «снять аудио», массовые операции, размеры | Единственная часть, теряющая данные, — едет отдельно, с тестами на то, что удаляется ровно один каталог |
| 4 | Политики хранения | Автоматика поверх непроверенного удаления — способ потерять архив по таймеру |
| 5 | Пользователи: CRUD, смена своего пароля, защита последнего админа | |
| 6 | Вебхук в базе, тестовый вызов, блок документации | |
